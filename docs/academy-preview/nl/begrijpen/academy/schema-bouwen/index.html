Je kunt een Premium-schema met Server, switch, gateways, DALI-deelnemers en gebouwbeheer zelf opbouwen en per verbinding de juiste soort kiezen.

Schema bouwen · Verdieping

Bouw het Premium-schema zelf op

Een kantoorgebouw met twee verdiepingen krijgt LiveLink Premium met een Server in de technische ruimte. Iedere verdieping krijgt een eigen Ethernet/DALI Gateway met DALI-deelnemers. Het gebouwbeheersysteem bedient centrale functies. Het schema is deels leeg: bouw het zelf op.

  • Server en gateways staan op een eigen netwerk; het gebouwbeheer koppelt via BACnet/IP.
  • Iedere gateway krijgt een eigen netwerkaansluiting op de centrale switch.

1 Zet de onderdelen op de lege plekken (nummers) en kies voor iedere open verbinding (letters) de verbindingssoort.

Kies een onderdeel of verbindingssoort en tik dan de lege plek (nummer) of de open verbinding (letter) in het schema aan. Of gebruik de keuzelijsten eronder. Controleer daarna.

Verbindingssoorten

Bekijk uitleg

In de technische ruimte staan de Premium Server en de Ethernet-switch; de Server praat via Ethernet met de switch. Iedere Ethernet/DALI Gateway hangt met een eigen Ethernet-kabel aan de switch en levert de DALI-lijn naar de deelnemers op zijn verdieping. Het gebouwbeheer koppelt via BACnet/IP over hetzelfde netwerk; het is geen DALI-deelnemer.

Uit de kennisbank

Controller of Server en iedere gateway krijgen een eigen aansluiting op de centrale switch; LiveLink Premium-componenten worden niet onderling doorgelust via hun Ethernet-poorten. Dat is een TRILUX NL-ontwerpuitgangspunt: de officiële documentatie beschrijft de opbouw via een switch en spreekt zich over doorlussen niet uit.

Via de gateways ziet de centrale unit alle aangesloten DALI-lijnen. Op een DALI-lijn zitten armaturen, sensoren en drukknopkoppelaars.

2 Waarom krijgt iedere gateway in dit schema een eigen kabel naar de switch, en niet een kabel vanaf de vorige gateway?

  • Omdat TRILUX NL per fysieke aansluiting een eigen verbinding ontwerpt: storingen zoeken, uitbreiden en vervangen blijft dan per gateway overzichtelijk.
  • Omdat de DALI-lijn anders te lang wordt.
  • Omdat de Server maar één gateway tegelijk kan aanspreken.
